# SPEC v0.1 — локальный конструктор лендингов (`~/Builder`)

Источник решений: `IDEAS.md` (раунды 1–10), `GRILL.md` (открытые вопросы).
Правило: эта спецификация описывает MVP; всё, что помечено ⏭, — сознательно за бортом.

---

## 1. Что это

Локальный браузерный конструктор, который из заполненной формы (Brief) получает
готовый лендинг: HTML/CSS/JS + картинки + продающие тексты, с автоматическим
тестированием и самоисправлением. Один пользователь, один прогон, ноль внешних
серверов, кроме API моделей. Два режима: **White** (светлая тема конструктора,
широкие поля) и **Black** (тёмная тема, узкие поля прелендов, правила серии
зашиты в пресет/валидатор).

## 2. Технология (финальный выбор)

| Слой | Решение | Комментарий |
|---|---|---|
| UI | **React 19 + Vite + TypeScript** | Brief, план, события — одни типы на фронте и бэке |
| Сайдкар | **Fastify 5 + tsx** | SSE + валидация по JSON-schema, ~150 строк |
| Модель | **OpenAI-compatible адаптер** + реестр подключений | новые провайдеры = запись в конфиг |
| Картинки | **image-подключения**: task-протокол (kie…) или `imagening` (generations) | рабочий: imagening.click |
| Тесты | **playwright-core** (chromium из кэша, `--disable-dev-shm-usage`) | скриншоты 3 брейкпоинтов + console + DOM |
| Хранение | файлы: папка проекта + `settings.json` + `run.jsonl` | без БД |
| Запуск | `npm install && npm start` → сам открывает `localhost:5173` | vite proxy → `/api` |
| Шаблоны промптов | `prompts/*.md.jte`, версионируются, хэш в кэше | не строки в .ts |

Никаких нативных зависимостей с компиляцией (node-gyp) — передача коллеге не должна
ломаться. Порты из конфига, занят → следующий свободный.

## 3. Структура

```
~/Builder/
  package.json            # npm workspaces
  settings.json           # подключения, роли, lanes, gates, projectsRoot
  .env                    # BUILDER_OPENROUTER_KEY, BUILDER_KIE_KEY, ...
  prompts/                # white|black × plan|copy|image-prompts|page-code|fix
  packages/
    shared/               # TS-типы: Brief, SitePlan, Manifest, OrchEvent, Connection
    server/               # Fastify, RunManager, Scheduler, runners/, connections/
    web/                  # React: форма → gate плана → монитор → превью; сайдбар моделей
  projects/               # один прогон = одна папка (projectsRoot настраивается)
```

## 4. Модельный слой

- **Connection** = { id, name, kind: llm|image, baseUrl, auth {env|local},
  protocol: openai-chat | task-poll | custom, models[], vision?, limit{mode}, enabled, priority }
- **Роли** (не видны юзеру как сущности): `code`, `copy`, `vision`, `image` —
  это связка «модель + шаблон промпта + параметры (temp, max_tokens)».
- **UI выбора — плашки подключений** (kind llm и kind image разделены ролью):
  название = определённый провайдер, под ним фактический лимит, ниже пилюли
  моделей; клик по пилюле назначает модель на роль (код или картинки) и действует
  сразу, в том числе посреди прогона — раннеры читают selection на каждом запросе.
  Ключ — одно поле: `POST /api/connections/detect` определяет провайдера по
  префиксу ключа и перебором известных эндпоинтов; адрес — вторым полем только
  когда ключ его не подсказал (self-hosted).
- **Vision зашит**: определяется проверкой подключения (пинг «png + что на картинке»),
  выбирается алгоритмом (активная llm → первая vision-модель реестра → детекторы без зрения).
  Прогон без vision = предупреждение один раз, не блокировка.
- **Квота у подключения, цена у модели.** Лимит **констатируется, а не назначается**:
  галки «безлимит» нет — провайдеру нельзя указать тариф, можно только спросить.
  Строка под названием подключения = что ответил его API (`/key`, `/credits`, очередь
  генераций Imagening); не ответил — «? провайдер не отдаёт лимит», а не выдуманное
  число. Пороги 20%/5% красят строку, при 0 — авто-fallback на следующее подключение.
- Смета до прогона: картинки + токены + vision-скриншоты, в карточке gate.

## 5. Brief и данные

- White: город, №white, ниша/оффер, заголовок/подзаголовок, палитра, аватар/тип,
  секции+порядок, тон, контактные данные, PHP-опции. Обязательные поля — 4.
- Black: красный hex, тип/аватар, оффер, caption'ы, ролик да/нет. Константы серии
  (black_NNN, assets-black, webp-only, трек-клик, PHP-шапка, без Privacy/Terms,
  no-repeat red из `LANDING_REGISTRY.md`) — валидатор, не поля.
- Brief → `brief.expanded.json` (LLM-разворачивание из 1 строки, diff на подтверждение)
  → **`site-plan.json`** — контракт: секции, заголовки, slug-имена картинок, палитра.
- Ручные правки живут в `overrides.css|html`, оркестратор их не трогает.

⚠ Открыто: whites-серия на деле **многостраничная** (`wp-*/index.php + about/ contact/
services/ policy/ terms/ thanks/ + site.config.json + sitemap + llms.txt`).
MVP генерит одностраничник; экспорт в структуру whites (site.config.json + php-обвязка
+ zip) — пост-шаг. Решить при первой реальной сборке white.

## 6. Оркестрация

```
UI ── SSE/REST ──► RunManager (1/прогон, AbortSignal)
                        ▼
                   Scheduler (DAG, lanes, gates, fix-цикл)
                        ▼
              Runners: llm · image · browser · fs
                        ▼
              Connections (единственный сетевой слой)
```

Граф: `brief → expand? → plan → ⛔gate → (copy ∥ image-prompts→imgs[N] ∥ code) →
assemble → shoot → judge → [fix ≤2 → shoot → judge]* → export → report`.

- lanes: `{ llm: 2, image: 4, browser: 1 }`.
- Истина на диске: `run.jsonl` + артефакты; рестарт пропускает задачи с валидным хэшем.
- Кэш промптов: хэш(promptVersion, role, model, input, seed) → `.cache/prompts/`.
- Ошибки: transport → retry×3; contract → 1 самокоррекция со текстом ошибки;
  quota → fallback/пауза; fatal → needs_human. 500-шторм (3 ошибки роли подряд) → пауза.
- Команды UI: start · pause · resume · cancel · skip · retry(task) ·
  regenerate-images(failed) · fork(variant) — все события в run.jsonl.
- Картинки: retry×2 (вариация промпта) → fallback-подключение → SVG-плейсхолдер
  в палитре по slug из плана → needs_human. «Догенерить картинки» = отдельная
  пост-операция без переписывания HTML.

## 7. Gate после плана (единственный, по умолчанию)

Карточка: секции-карточки (тип, H2, slug) · палитра-плашки · картинки «slug → описание» ·
смета. Кнопки: **Поехали** (Enter) · Править · Перегенерить с комментарием · JSON ▾.
3 автопринята подряд → предложить автостарт с undo-тостом (3 с).

## 8. Тестирование и фикс

MVP: собранность/404 · console-errors · layout-shift/overflow/пустые блоки ·
контент-анкоры (cta/price/phone) · битые href · скриншоты 375/768/1280 ·
vision-пасс по чек-листу · red-no-repeat (black). `impeccable detect --json` — по флагу.
Fix: ≤2 раунда, модели шлётся **только CSS/HTML-патч + дефект + селектор**;
стоп «готово» = критичные проверки зелёные, иначе `needs_human` с отчётом.

## 9. UI конструктора

- Витрина генератора: **тема одна — тёмная** (светлая упразднена); White/Black осталось
  только как режим лендинга, витрину оно не перекрашивает.
  **Заголовка-витрины нет**: первым блоком идёт конструктор выбранной сборки (его поля
  занимают место тайтла), табы White/Black меняют набор полей на этом же месте.
  Полотно кода — **не в hero, а под всей страницей** (fixed-слой, кромка = сайдбар),
  кроме футера: SVG-анимация **единым полотном кода** на всю ширину (не колонки),
  бесконечный цикл, подсветка синтаксиса, без рамок/вкладок «редактора», без свечения,
  **без моргающего курсора**, **без перспективы** — полотно плоское, начинается сразу
  от сайдбара; строк-линеек нет (не сходятся с набором, смотрятся инородно),
  скорость ленты 592 c на цикл.
  Настройки зашиты в генератор (0.35× / плотность 0.5 / прозрачность 30%) и юзеру не
  показываются. `prefers-reduced-motion` замораживает. Артефакт: `assets/hero-svg/hero-code.svg`.
- Layout: без коробки-контейнера, `max-width: 1920px`, **слева сайдбар**:
  два таба White/Black → индикатор сети → панель моделей. Навигация по разделам
  и список «Прогоны» убраны: страница одна, якорям некуда вести, а расположение
  проектов у юзера своё (настраиваемый `projectsRoot`) — вшитый список папок
  был бы обещанием, которого генератор не даёт. Табы White/Black выбирают режим
  и открывают на витрине свой набор полей/селектов
  (`packages/web/src/brief-form.tsx`); введённое в другом режиме не теряется.
- Все контролы — свои, системные виджеты не показываем: `<select>` заменён своим
  (клик вне / Escape закрывают), скроллбары тонкие, в акценте, видены всегда
  (hover лишь усиливает), единый стиль для lists/textarea/страницы.
- **Связь разделена на два индикатора.** В сайдбаре — сеть: 10 равных делений
  (ширина кратна физическому пикселю) и одна короткая подпись из четырёх
  («сеть есть / плавает / лагает / нет интернета»); вайфай и интернет из WSL
  измерить раздельно нельзя, поэтому подпись одна. У каждого подключения свой
  индикатор: 5 делений = последние события связи с провайдером (бесплатные
  проверки живости каждые ~12 с + рабочие запросы прогона), цвет по HTTP-коду,
  один 5xx в ленте красит вердикт. Данные — из серверного монитора
  (`net/monitor.ts`, шаг 3 с), одним SSE-потоком на страницу.
- Нет image-подключения/модели → прогон НЕ стопорится: SVG-плейсхолдеры в палитре
  по slug, догон картинок командой `regen-images` (илиmanual-подстановка файлов).
- Рабочий экран: слева Brief-форма (аккордеоны), в центре события/артефакты прогона
  + iframe-превью, справа сайдбар подключений (бейджи квот, «Проверить», «+ подключение»).
- Мастер первого запуска: ключ → проверка → папка проектов (3 шага).
- Doctor: `npm run doctor` — Node, ключи по именам env, chromium-кэш, порт.
- Авто-деградация без Chrome / без ключа: серая плашка с причиной, не падение.
- История прогонов: список с фильтром, «дублировать с изменённой Brief».

## 10. Артефакт прогона

```
projects/<id>/ brief.json · brief.expanded.json · site-plan.json · copy.json
  prompts/*.rendered.md · assets/img/* (webp) · dist/ · preview/*.png
  overrides.css|html · run.jsonl · report.md
```
Black-экспорт: `black_NNN/` (следующий свободный с учётом пропусков 026–035) +
предзаполненная строка в `LANDING_REGISTRY.md`. White-экспорт: ⚠ см. §5.

## 11. MVP-скоуп (перезвон не нужен, принято)

Brief-форма (4 обязательных поля + «развернуть») · prompt-program 5 шаблонов с кэшем ·
plan → gate → (copy ∥ images ∥ code) → assemble → shoot → judge → fix×1 → report ·
подключения: OpenRouter + kie.ai, два селекта, бейджи квот · playwright-проверки §8 ·
ручной режим картинок (none/manual с первого дня) · история прогонов.

⏭ Варианты (variants), Monaco, live-редактор «клик по элементу», мультиязычность,
Lighthouse, gates на copy/images, многостраничник, серверный режим.
