# AGENTS.md — `~/Builder` (локальный конструктор лендингов)

Читать вместе с `SPEC.md` (что строим) и `IDEAS.md` (почему именно так, раунды 1–10).
`GRILL.md` — закрытые открытые вопросы. Этот файл — рабочие правила и текущее состояние.

## Что это
Brief (форма) → JSON → мастер-промпт → модели → сборка → съёмка в Chrome → vision-судья
→ фиксы (≤2) → готовый лендинг. Локально, один юзер, один прогон, внешнее — только API моделей.
Два режима: **white** (светлые лендинги, широкие поля) и **black** (тёмные преленды,
константы серии в валидаторе, не в полях).

## Стек (финально, не переобсуждать)
React 19 + Vite + TS · Fastify 5 + tsx · npm workspaces (`shared` / `server` / `web`) ·
playwright-core (chromium из кэша) · файлы вместо БД (`projects/<id>/`, `settings.json`, `run.jsonl`).
Никаких нативных зависимостей с node-gyp — генератор отдаётся коллеге.

## Правила кода (проверено, ломалось)
- **Прогон типов после каждой правки**: `npm run typecheck` (из корня). Правки, где `switch`
  по union сузился до `never`, выносить в отдельную функцию-помощник (`step()` в render.ts).
- pi-lens заглушки вида `case "x":` не прощают: union-разбор должен быть полным.
- `JSON.parse` файлов с диска — всегда через `readJsonSafe` / try-catch (иначе падает прогон).
- Раннер ничего не знает про провайдеров; сеть — только `connections/`.
- Правда прогона на диске (`run.jsonl` + артефакты), в памяти — только слушатели SSE.
- Ошибки 4 класса: transport → retry×3 экспоненциально; contract → 1 самокоррекция с текстом
  ошибки; quota → fallback-подключение, нет fallback → пауза; fatal → `needs_human`.
  3 транспортные ошибки подряд = 500-шторм → пауза, не ретрай-шторм.
- `browser` lane = 1 жёстко (7.8 ГБ RAM). Рендер/тесты — `--disable-dev-shm-usage`.
- Шаблоны промптов — только `.md.jte` (версируются, хэш идёт в кэш). Ответ модели — **только
  JSON**, без markdown-ограждения; парсер снисходительный (срезать ```json).
- В промптах язык обращения к модели — русский, промпты картинок — английский.
  Шрифты для кириллицы называть явно (Inter, Manrope, Oswald, PT Sans, DejaVu Sans).

## Конфиг и ключи
- `settings.json` — подключения, роли, lanes, gates, `projectsRoot`, `maxFixRounds`.
- `.env` — ключи с префиксом `BUILDER_` (`BUILDER_LITELLM_KEY`, `BUILDER_IMAGENING_KEY`, …).
  Руками их не вписывают: ключ из сайдбара пишет сама форма (`setEnvLocal`), имя переменной =
  `BUILDER_<id подключения>_KEY`, а в `settings.json` уезжает только имя. Не путать с чужими
  ключами машины (`OPENROUTER_API_KEY`, `ZAI_API_KEY` — генератор их не читает).
- От юзера на подключение **один API-ключ**: `POST /api/connections/detect` определяет
  провайдера по префиксу ключа (`sk-or-`, `imk_`, `gsk_`, …) и проверяет адрес запросом
  (`/api/v1/models` → llm, imagening-generations → image). Адрес — второе поле, и только
  когда префикс незнаком: ключ хост не несёт.
- Лимит **констатируется**, а не назначается: галки «безлимит» больше нет, мы не можем
  указать провайдеру тариф. `limitBadge` спрашивает API (`QUOTA_PROBES` по хосту/протоколу:
  OpenRouter `/key`, OpenAI `/dashboard/billing/subscription`, openai-совместимые `/key/info`,
  imagening `/api/v1/me` → очередь) и показывает что получил; не получил — «? провайдер не
  отдаёт лимит», а не выдуманную единицу.
- Квота **у подключения**, цена **у модели**. Vision определяется пиингом, не галочкой юзера.
- Подключения по факту: `litellm` (наша серверная `qwen/qwen38-flash-next`,
  `https://llm.dirigent.cloud/v1`) и `imagening` (картинки, протокол `imagening`).
  Kie.ai живым ключом пока не проверен (`/api/v1/models` без ключа отвечает 401, т.е.
  авто-детект по `GET /models` для него не сработает — нужен адрес + ключ).
- `imagening` из `~/.local/bin` — внутренний инструмент, но как image-подключение он работает:
  HTTP-API `POST /api/v1/generations` → поллинг `/api/v1/generations/{id}` → файл по
  `outputs[].file` с тем же Bearer.

## Правка должна быть ВИДНА (09.11, white_001)
Жалоба «после правки в браузере ничего не изменилось, функционал мёртв» состояла
из трёх независимых дефектов — все закрыты, проверено боевым раундом в браузере:
- **Превью живёт в ОТДЕЛЬНОЙ вкладке (решение юзера, от iframe в карточке
  отказался: «сжирает всё пространство»)**. Чтобы вкладка не стояла устаревшим
  кадром, `GET /projects/:id/dist/index.html` — ЯВНЫЙ роут (не статика), который
  подмешивает перед `</body>` скрипт `builder-live`: раз в 4 с сверяет
  `/api/projects/:id/site`.builtAt (mtime dist) и делает `location.reload()`,
  когда сборка стала новее. Проверено: правка из карточки → вкладка
  перезагрузилась сама через 5 с, заголовок сменился 86.4px → 54.4px. Роут
  отдаёт ТОЛЬКО главную; вложенные страницы и ассеты — статика. `?v=<builtAt>`
  в ссылке остаётся на случай ручного открытия.
- **`builtAt` (mtime `dist/index.html|php`) в `/api/projects/:id/site`** — без него
  UI не мог отличить результат от истории и вчерашний «правки: 1 из 1 · 7 нояб.,
  18:20» горел зелёным как статус свежего действия («зачем вылезла плашка, если
  ничего не применили»). Плашка теперь: `правка применена` (зелёный/янтарный,
  `lastFix.builtAt === builtAt`) или `правок в истории` (серый, класс `.hist`).
- **`changed` в `human-fix.json`** — хэш `dist/index.html` до/после пересборки
  раунда («патч дописан в overrides» ≠ «страница изменилась»): при `false` и
  финальная строка, и плашка честно говорят «собранный файл не изменился» и
  предлагают откат. Отказаться в пользу `landed` (поиск метки в dist) нельзя:
  метка могла присутствовать от РАНИЕЕ применённого раунда.
- **«Убери дубли картинок» — модель чинила НЕ ТО: патч применялся, а дубль
  оставался** (09.11, white_001). Модель не видела, ГДЕ стоит каждая картинка:
  в промптах были только список файлов и карта секций. Реальный дубль — секции
  `gallery` и `campus-gallery`, печатающие одни и те же 6 файлов, а модель
  прятала `img` внутри feature-плитки (`display:none` сработал, и «✓ готово»
  было правдой про патч, но не про жалобу). Лечится `imageMap(html)` — в все
  фикс-промпты добавлена карта `файл → секция` + строка «ПОВТОРЯЮЩИЕСЯ src:
  …xN», и правилом править СЕКЦИЮ из строки. Замер после: скрытием
  `#campus-gallery` видимых картинок стало 15 → 9, повторов секций нет.
- **Все строки карточки «Нужны действия» обязаны датироваться**: вердикт суда и
  машинные проверки после human-fix НЕ переснимаются, и вчерашний «vision-судья:
  критичных 1» висел как нынешний. `/site` отдаёт `verdictAt`/`checksAt` (mtime
  `preview/verdict-rN.json`, `checks-rN.json`), UI дописывает «снимок от …» и,
  если dist новее, «сборка новее» / «НЕ переснималась после правок».
- **Дедуп правок между СОБОЙ (`collapsePatch`) — реальная причина «правки нет,
  даже после F5»** (18:56, белый футер): `overrides.html` — список раундов, и
  каждая правка футера дописывала СВОЙ <footer>; старый `<footer id="footer">`
  из прошлой правки вырезался только из БАЗОВОЙ вёрстки (dedupeOld), а между
  раундами дубли не схлопывались → в dist жило 2 футера, новый — ПОД старым.
  Теперь перед вставкой пачка правок (и overrides, и фиксы) прогоняется через
  `collapsePatch`: при повторе id или повторном <footer> остаётся ПОСЛЕДНЕЕ
  вхождение. Замер: 2 футера → 1 (живой, с Explore/Legal/Contact).
- **Поле правки и кнопка «Допилить» — одной высоты** (`align-items: stretch` +
  `min-height: var(--control-h)` на textarea и на `.review-fix .btn.sm`): с
  `flex-start` 38-px кнопка висела рядом с двухстрочным полем.
- Заметка модели по ОДНОМУ пункту больше не теряется: `lastFix.items[0].note`
  показывается в `.rf-note` (раньше её было видно только в `_note` лога).
- **Vite на этой машине умеет отдать ПУСТОЙ модуль** (не только CSS): после правок
  `brief-form.tsx` отдавался с 200 и нулевым экспортом → `SyntaxError: does not
  provide an export named 'default'`, белый экран с `#root` без детей. Лечится так
  же — `touch` файла; проверять `curl :5173/src/<file>.tsx | wc -c`.

## Адресность правки + эскалация модели (09.11, по разбору внешнего ревью)
- **`sectionOfOrder` + `cssForFragment` в humanFix**: по тексту заказа
  выбирается целевая секция (русские слова-указатели «футер/галерея/форма/…»
  → id секции), модели отдаются ЕЁ html и только те CSS-правила, чьи селекторы
  в ней встречаются; остальная палитра имён — списком `cssRest`. Замер живьём
  («увеличь отступы внутри футера»): контекст 21.5k → 15.1k симв., в
  prompts/*.rendered.md видно «Фрагмент = секция „site-footer“», патч — с
  первой попытки. Без совпадения — прежнее поведение (первые 3k html).
- **Эскалация**: `settings.fixEscalation` (сейчас openrouter/
  anthropic/claude-sonnet-5.5) — третья попытка правки идёт на сильную модель,
  если дешёвая дважды не изменила страницу. Транспорт: `ModelRequest.
  modelOverride` (types.ts) + переупорядочивание пула в callLlm; override
  действует только на своё подключение и только если модель есть в его
  реестре (иначе «unknown model» на чужом провайдере). В кэш-ключ модель
  входит — эскалированный ответ не путается с кэшем дешёвой.
- Смысл разделения: попытка 1 — копейки, попытка 2 — тот же заказ + упрёк,
  попытка 3 — сильная модель; ложного «готово» ни на одной из них нет
  (проверка хэша dist общая).

## «Модель не слушает правки» → цикл с проверкой и переделкой (09.11)
Роль fix — дешёвая flash, и она систематически выдавала патч-ИМИТАЦИЮ
(«Заменены все дублирующие картинки через CSS content», а хэш dist — байт в
байт прежний). Точечные правила в промпте кончились: теперь механизм ловит
это сам, в `humanFix`:
- **Раздел `appliedPatches` в фикс-промптах**: модель видит, что уже применено
  (текущие overrides + swaps + id html-дописок). Без него она «чиныла» заново
  уже сделанное, и раунд не менял ничего.
- **Раунд, не изменивший хэш dist, — не успех**: патч откатывается с диска
  (css/html-блок по roundId + строки img-swaps) и модель переспрашивается с
  конкретным упрёком («ТВОЙ ПАТЧ НЕ ИЗМЕНИЛ СТРАНИЦУ НИ НА БАЙТ… не имитируй,
  css не может менять src»). Кэш-ключ попытки обязан содержать `-r2` + хэш
  упрёка: после отката overrides прежние, и без него повтор достал бы из кэша
  тот же провалившийся патч.
- Вторая неудача = **ok:false** «модель дважды прислала патч, который не меняет
  страницу… Сайт прежний, раунд откачен» — вместо прежнего ложного «✓ готово».
  Успех со второй попытки помечается `retried` и «(со второй попытки)» в строке.
- Откатывающий assemble — С `await` (без него два assemble писали один dist
  параллельно).

## Замены картинок = поле `swaps` (09.11): css не умеет менять src
«Замени дубли картинок» → модель отвечала `background-color` («Заменены…
через CSS content · страница пересобрана · 0 → 0», пиксель тот же): src <img>
не выразить ни css-патчем, ни html-патчем (тот дописывается в конец body).
- Фиксер отвечает полем `swaps: [{from,to,which}]`; humanFix валидирует `to`
  по диску, пишет `img-swaps.json` (метка roundId), `assemble` подменяет N-е
  вхождение src; undo-fix срезает раунд и из swaps-файла (id раунда ищется и
  там — раунд бывает swap-only). Флаг `changed` честно поймал первый такой
  промах («собранный файл не изменился»).
- Совпадение `from` снисходительное по ОСНОВЕ имени (model зовёт
  gallery-metro.jpg, на диске .webp) — как у remapLooseImgs, иначе swaps не
  попадали.
- Настоящий дубль картинок в white_001 был не в галерее: фикс r2 дописал
  три <figure> ПОСЛЕ футера как заплатку на битые src; когда src починились,
  заплатка осталась и печатала повтор. Лечится обнулением build/fix-rN.html,
  не промптом. Доведено детерминированно (swaps manual1 + обнуление fix-r2):
  7 уникальных картинок, повторов 0, загрузка без 404 (проверено скроллом —
  lazy-load и naturalWidth).
- Из карточки удалены декоративные кнопки «⤓ Выгрузить · <пилюля>» ×3 и
  «в папку…» (см. правило «кнопки либо работают, либо их нет»).

## Вкладка правки = пульт (09.11): кнопки либо работают, либо их нет

## Ревью перед выгрузкой (раунд 06.11)
Логика выгрузки переписана: «собрать» и «выгрузить» — разные действия.
`plan → gate → copy/code/img → assemble → shoot → judge → fix≤2 → export → report →` **`review`**
и дальше по команде человека: `accept` (в done без копий) / `deliver` (копия+zip → done) /
`human-fix` (патч → обратно в review).

- **`review` — новое состояние** (`RunStatus`), между «сборка готова» и `done`.
  В `done` прогон уходит ТОЛЬКО по команде человека. `graph.ts` больше не вызывает
  `placeWhite` изнутри `exportSite`: экспорт собирает `export/`, а за пределы
  мастерской проект уходит явным `tasks.placeExport()` (роут `POST /api/projects/:id/place`).
  Выбор цели в брифах остался, но он теперь только настройка кнопки.
- **Кнопка «▶ Смотреть»** у кнопки генерации: отключена до сборки, активна после.
  Открывает `http://localhost:8710/projects/<id>/dist/index.html` (тот же корень, что у
  хостинга, а не `file://`) + `cache-control: no-store` на всех `/projects/*` — раньше
  Vite/Chrome консервировали CSS и это выглядело как «стили слетели».
- **`human-fix` = человеческий фикс-раунд, а не перегенерация**: тот же `prompt/fix`,
  но патч пишется НЕ в `build/fix-rN.*` (их читает конкретный раунд), а в
  `overrides.css` / `overrides.html`, которые `assemble` дописывает в конец и которые
  оркестратор не переписывает. Дальше `assemble` + `shoot` (машинные проверки),
  vision-судья НЕ зовётся (экономия токенов, смотрит человек). Раунды не ограничены
  `maxFixRounds`. Пустой ответ модели = **ошибка раунда** с текстом, а не молчаливый
  успех (лечит «патч по дефекту m7 пустой»).
- **`placed.json` в папке проекта** = факт реальной выгрузки (куда, когда, stamp=
  mtime export/index.html). «Устаревшая копия на столе» = `stamp` вырос после выгрузки,
  UI показывает «выгрузите заново». Свип при старте сервера судит о «выгружено» по
  нему, а не по `brief.delivery.kind` (иначе `done` без выгрузки уезжал бы в archive).
- **Прогон можно перезапустить**: `review` не считается трупом (свип его пропускает),
  а если сервер всё же перезапустили и оркестратора в памяти нет, карточка ревью
  работает дисковыми роутами: `POST /api/projects/:id/{human-fix,place,accept}` +
  GET `/api/projects/:id/site` (снимок: built/url/placed/stale/verdict/checks).
- **Библиотечный zip был сломан всегда**: временное имя `.site.zip.tmp` не кончается
  на `.zip`, python `make_archive` дописывает расширение, а страховочный
  `rmSync(zipPath + ".zip")` в `makeZip` стирает ровно готовый архив → в `index.json`
  всегда `zip: ""`. Временное имя обязано кончаться на `.zip` (`.site.tmp.zip`).
- Правка в review обязана передавать **раунд последнего вердикта** в `TasksCtx.round`:
  `assemble` читает `build/fix-r<round>.html`; с `round: 0` человеческая правка молча
  вернула бы HTML до автофиксов.
- В UI review: `RunActivity` не прячет карточку на время правки (прогон в `running`),
  карточка сама показывает «Допиливаю…» и опрашивает `/site`; панель «Проекты»
  показывает review-строки с подписью «ждать просмотра».
- Dev-хук: `?review=<id>` открывает карточку ревью для готовой папки без прогона
  (рядом был `?gate=1`).
- **Пустой CSS в HMR — вечная болячка Vite на этой машине**: если править
  `styles.css` ДОПИСКОЙ (`cat >>`) или иным внешним processом, vite читает файл
  в момент записи и консервирует `__vite__css = ""` — страница становится голой
  («стили слетели»), файл при этом полный. ВТОРОЙ подтверждённый триггер (07.11):
  `npx vite build packages/web` при ЖИВОМ dev-сервере — билд трогает тот же
  `dist/`, и раздаваемый HMR CSS так же обнуляется. Лечится прикосновением
  (`touch packages/web/src/styles.css`); проверять `curl :5173/src/styles.css | grep
  __vite__css` (должен быть длинный ответ, а не `= ""`). Правки через edit/write
  этого не дают.

## Картинки: формат, вес, имена (раунд 06.11, white_001)
- **WebP для обоих режимов** (было: webp только у black). PNG от генератора =
  250–700 КБ/шт; тот же кадр в webp = 60–250 КБ. `toWebp()` вызывает ffmpeg с
  `scale=1600:1600:force_original_aspect_ratio=decrease` (кадр ДЛИННОЙ стороны,
  не ширины: у портрета 3:4 широкая сторона и так <1600) и `-q:v 78`.
  Нет ffmpeg → остаёмся на исходнике, прогон не падает.
- **dist/assets/img чистится перед копированием**: после перевыпуска картинки в
  другой формат старая копия жила в dist вечно и уезжала в экспорт.
- **svg-плейсхолдер удаляется**, как только у slug появился растр
  (`cleanStalePlaceholders`), иначе в архиве две копии одной картинки.
- **`remapLooseImgs` теперь: (а) prefers raster над svg** при одном корне имени
  (Map.set отдавал победу последнему из readdir → svg-заглушке); **(б) мемоит
  выдуманное имя** (одно имя в карточке + lightbox тянуло два разных файла);
  **(в) при нуле совпавших слов берёт любой свободный файл** — битая иконка
  хуже, чем фото из той же пачки; **(г) применяется и к `overrides.html`, и к
  `build/fix-rN.html`** — фикс вставляет свои `<img>` с именами из головы модели,
  и именно отсюда рождались «битые картинки», которые CSS-фиксер чинить не может.
- **«fetch failed» больше не сжигает прогон**: у картинки свои 3 попытки с
  паузами до плейсхолдера; сетевой сбой помечается `status: failed` (а не
  `placeholder`), и кнопка «Догенерить картинки»
  (`POST /api/projects/:id/regen-images`) добирает их и ПЕРЕСОБИРАЕТ сайт —
  без токенов на тексты и вёрстку.
- **Шторм считается по упавшим ЗАДАЧАМ, а не по попыткам**: три ретрая одной
  задачи-судьи ставили весь прогон на паузу на первом же сбое сети.

## Правки раунда 07.11 (журнал, ревью, удаление)
- **`DELETE` без тела + `content-type: application/json` = 400 ещё до роута**
  (`FST_ERR_CTP_EMPTY_JSON_BODY`, Fastify). Общий `j()` в `api.ts` ставил
  заголовок всегда → молча ломал и удаление проекта, и `deleteConnection`.
  Заголовок теперь только при наличии тела.
- **`position: sticky` создаёт stacking context**: модалка внутри `.sidebar`
  с `z-index: 60` оставалась ПОД `.brief` (`z-index: 1`) соседней колонки.
  Подтверждения/оверлеи из сайдбара — только `createPortal(…, document.body)`.
- **Удаление проекта**: `DELETE /api/projects/:id[?full=1]` — живой прогон
  сначала отменяется, `full` сносит и снимок в библиотеке. В UI — корзина в
  строке панели + модалка (Esc / клик по подложке = отмена, «Удалить совсем»
  только когда есть библиотечный снимок).
- **Журнал прогона**: буфер больше не режется (`slice(-7)` был причиной
  «модель пропускает таски»), панель крутится сама и доворачивается за новым
  концом, пока пользователь не открутил вверх (>40 px от конца).
- **Список правок применяется весь за один заход**: `splitEdits` → шаблон
  `fix-list.md.jte` (спрашивает `done` с каждого пункта), отчёт в
  `human-fix.json`, наружу — `review.fix` + `site.lastFix`; карточка ревью
  показывает «✓ все правки внесены (N)» или «N из M» с перечнем пропущенного.
- **Шлюз после плана — янтарный `--sig-warn`**, не красный: план готов и
  ждёт, а красный читался как экран ошибок. Красный остался ошибкам.
- **Палочки здоровья модели = уровень, как у сети**: ok → 5 зелёных +
  пульс последней (эквалайзер 5 ⇄ 4), warn → 3 жёлтые, bad → 2 красные.
  Пульс только в зелёном: мигать при 429 — перекричивать соседа, у которого
  реально сломано.
- **Dev-хуки витрины** (только `import.meta.env.DEV`): `?review=<id>`,
  `?gate=1`, `?net=bad|warn` (провайдер картинок «лёг»: 2 красные / 3 жёлтые,
  лента = был и оборвался), `?pending=N` (баннер «картинок-заглушек» на
  обычной сборке). Симуляция подменяет СОБЫТИЕ в `net-stream`, а не компонент:
  индикатор сети, плашки моделей и ревью читают один поток.
- **Пустой `href` — не «ссылка в никуда»**: браузер открывает ТЕКУЩУЮ страницу.
  У отменённого до сборки вайта имя в панели было `<a href="">` и клик открывал
  генератор в новой вкладке. Нет сборки — имя рендерится `<span>` (`.project-id.dead`),
  а не ссылкой с пустым href.
- **Палитра: плитка 150 px и ТРИ ряда — решение юзера, не регрессия.** Аудитор
  (11.07) просил 2 ряда через `minmax(100px,…)`; на живом экране плитки вышли
  мелкими, а компактная плитка ещё и выталкивала попап «своей пары» за правый
  край. `.grid{padding-bottom:84px}` от того же аудита ОСТАЛСЯ — он лечит
  закрытые липкой панелью пилюли (unreachable 0), рядов не касается.
- **Формат индексов (`index.html` / `index.php`) больше не поле брифа**: это
  свойство сервера, куда несут сайт, поэтому переключатель стоит в ряду кнопок
  выгрузки карточки ревью (`POST /api/projects/:id/format`). Конвертируется
  сам `export/` без перегенерации, и туда же правится `brief.php`, иначе
  ближайшая пересборка (правка, догенерение картинок) откатывает формат.
  В брифе `draft.php` остался как дефолт серии (`true` для white), без чекбокса.
- **Ловушка `new RegExp` из шаблонной строки**: `new RegExp(`[\w-]+`)` теряет
  бэкслеш и превращается в класс `[w-]` — молчаливо «не находит». В шаблонных
  строках только `\\w`. Так формат переименовывал файлы, но не ссылки внутри.

  портал в body (sticky-сайдбар стрижёт оверлеи, правило выше), показ с
  задержкой 260 мс: курсор пробегает список по пути к корзине.
  `object-fit: cover` + `object-position: top` — интересен первый экран.
- **Палочки здоровья: `opacity` в пульсе уводит деление в композитный слой.**
  Строка панели стоит на дробной Y (`top 424.64`), Chrome растеризует слой по своей
  границе пикселя → последняя палочка уезжала на пиксель. `mh-eq` гаснет через
  `background` + `box-shadow` (тот же слой, что у соседей). Замер по пикселям: в
  погашенном состоянии палочка равна настоящей пустой (peak 43 = 43 у `t-empty`),
  профиль lit-палочки и пульсирующей в покое совпадает до 0. В headless офсета нет
  ни при каком `deviceScaleFactor` (1 / 1.25 / 1.5) — причина снята по логике, а не
  по воспроизведённому симптому.
